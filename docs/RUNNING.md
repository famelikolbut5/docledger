# Запуск Docledger

## Docker

```sh
docker compose up --build
```

Интерфейс и API: [localhost:8000](http://localhost:8000). PostgreSQL находится во внутренней сети Compose; наружу опубликован только порт приложения на 127.0.0.1.

Чтобы использовать другой порт, создайте `.env` на основе `.env.example` и измените `PORT`.

```dotenv
PORT=8818
```

Остановка без удаления данных:

```sh
docker compose down
```

Данные находятся в именованном томе `data`. Не удаляйте том, если нужны созданные записи. Начальные таблицы и примеры создаются при запуске; повторный запуск не перезаписывает записи.

## Разработка интерфейса

Нужны Node.js 22.12+ и npm. При работающем Docker-приложении:

```sh
npm ci
npm run dev -- --port 5173
```

Vite проксирует `/api` на сервер. По умолчанию в `vite.config.ts` указан порт 8000.

## Сервер без Docker

Подготовьте PostgreSQL 16 и пустую базу. Установите переменную окружения `DATABASE_URL` с параметрами своего подключения, например `postgres://user:password@127.0.0.1:5432/docledger`. Эти значения - пример, замените их собственными. Затем:

```sh
npm ci
npm run build
npm start
```

По умолчанию сервер слушает 127.0.0.1:3000. Для порта 8000 задайте переменную `PORT=8000` средствами своей оболочки.

Демо-пароль из Compose предназначен только для локального контейнера. Публикация сервиса требует авторизации и настройки под выбранное окружение.

## Проверки

Проверки выполняются против работающего сервера с настоящей PostgreSQL. Они создают тестовые записи; используйте демобазу.

```sh
npm test
```

По умолчанию используется localhost:8000. Для другого адреса задайте переменную `API_BASE_URL` средствами своей оболочки.

## Сценарий знакомства

1. Откройте документ и измените статус.
2. Проверьте историю, повторите тот же статус: нового события не будет.
3. Перенесите документ в архив, откройте раздел «Архив» и верните его в работу.
4. Создайте документ и найдите его по названию или контрагенту.
5. Выгрузите CSV и сравните сохранённые реквизиты.
